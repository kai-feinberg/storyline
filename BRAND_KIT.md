# Storyline Brand Kit

## Direction

**Option 1 — The Clear Path**

Storyline helps people understand what software does before asking them to understand how it is built. The identity should feel like a calm, welcoming guide through complexity: human-centered, clear, intelligent, and quietly technical.

## Core idea

**A gentle path through a complex landscape.**

The visual system turns code comprehension into a journey. Story comes first; behavior and implementation reveal themselves progressively along the way.

## Logo concept

An abstract S-shaped path inside a rounded rectangular frame, with a small opening that suggests progressive disclosure. The mark should remain simple, balanced, and recognizable at favicon size, in UI, and in print.

Avoid literal code brackets, terminal glyphs, generic sparkles, and overly complex diagrams.

## Voice

- Inviting
- Friendly
- Calm
- Clear
- Intelligent
- Human-centered

Preferred language is direct and reassuring. Explain what the product helps someone see, not how much technology sits underneath it.

Primary tagline: **See what the code is doing.**

## Palette

| Role | Color | Use |
| --- | --- | --- |
| Canvas | Warm ivory | Main backgrounds and paper-like surfaces |
| Ink | Deep navy | Headlines, wordmark, primary text |
| Accent | Soft coral | Key actions, active states, emphasis |
| Support | Pale mint | Secondary states, calm highlights, metadata |
| Neutral | Warm gray | Borders, inactive states, quiet surfaces |

Use coral sparingly and repeat it intentionally. Keep contrast soft but accessible; the product should feel warm without becoming playful or childish.

## Typography

Use a friendly humanist sans serif for display and interface text, paired with a restrained monospace accent for source locations, metadata, and implementation traces.

Typography should be spacious, readable, and hierarchy-led. Avoid tiny fake text, excessive all-caps, and dense technical labels.

## UI language

- Rounded story-step cards
- Clear progression and branch indicators
- Local expansion for semantic behavior
- Source-trace chips for implementation evidence
- Thin rules and generous whitespace
- Soft, restrained shadows
- Simple line icons

Dependencies and implementation details should feel like supporting context, never the primary visual story.

## Image direction

Warm editorial imagery: winding paths, layered paper landscapes, calm diagrams, tactile cards, and softly lit material surfaces. Images should feel art-directed and quiet, with subtle paper grain and no stock-office imagery or generic AI imagery.

## Design principle

**Represent code according to what it accomplishes, then reveal how it works only when more detail is useful.**
